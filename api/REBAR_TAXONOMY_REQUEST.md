# BriconLab API — 철근 계층 정보(사이드카) 제공 요청

## 배경

발주처(LH) 요청으로 **철근을 계층 구조로 분류해 트리로 선택·시각화**하는 기능을
사무소 대시보드와 현장 AR 앱 양쪽에 넣습니다. 옹벽의 경우 이런 형태입니다.

```
옹벽
├─ 전벽철근 ─┬─ 전면 ─┬─ 수직철근 ─ 01, 02, …
│            │        └─ 수평철근 ─ 01, 02, …
│            └─ 배면 ─┬─ 수직철근 ─ 01, 02, …
│                     └─ 수평철근 ─ 01, 02, …
├─ 저판철근 ─┬─ 상부 ─┬─ 횡방향 ─── 01, 02, …
│            │        └─ 종방향 ─── 01, 02, …
│            └─ 하부 ─┬─ 횡방향 ─── 01, 02, …
│                     └─ 종방향 ─── 01, 02, …
└─ 헌치철근 ──────────────────────── 01, 02, …
```

**개별 철근이 어느 가지에 속하는지는 도면에만 있는 정보라, 저희가 형상만 보고
복원할 수 없습니다.** 그래서 모델을 만드실 때 알고 계신 그 정보를 함께 주십사
요청드립니다.

**USDZ 파일 자체의 형식은 바꾸지 않습니다.** 계층 정보는 별도 JSON으로 받습니다
(이유는 §3).

---

## 요청 1 — 계층 정보 JSON 엔드포인트 추가

`GET /analysis/rebar-meta?ar_id={ar_id}` → JSON

기존 `GET /analysis/usdz?ar_id={ar_id}` 와 같은 `ar_id` 를 씁니다.
해당 모델에 계층 정보가 없으면 `404` 를 주시면 됩니다 — 앱·대시보드는 그 경우
형상 기반 자동 분류로 넘어가므로 기능이 죽지는 않습니다.

### 응답 형식

```jsonc
{
  "version": 1,
  "ar_id": "51120d35abdc44408520e22b4ff78d7e",
  "model_upload_at": "2026-08-05T10:22:31",  // 이 계층 정보가 대상으로 하는 USDZ 의
                                             //   ar-list 상 upload_at — 그대로 넣어주세요
  "prim_count": 248,                         // 그 USDZ 안의 철근 prim 총 개수
  "structure": "옹벽",                        // 트리 루트에 표시할 구조물 이름
  "rebars": [
    {
      "prim": "/RebarModel/Stem_Front_Vert_01",  // USDZ 안의 prim 경로 (조인 키)
      "label": "전벽-전면-수직철근-01",            // 화면에 그대로 뜨는 이름
      "path": ["전벽철근", "전면", "수직철근"],     // 트리 경로 (마지막 잎 제외)
      "no": 1                                    // 잎 번호
    },
    {
      "prim": "/RebarModel/Stem_Front_Horiz_01",
      "label": "전벽-전면-수평철근-01",
      "path": ["전벽철근", "전면", "수평철근"],
      "no": 1
    },
    {
      "prim": "/RebarModel/Base_Top_Trans_01",
      "label": "저판-상부-횡방향-01",
      "path": ["저판철근", "상부", "횡방향"],
      "no": 1
    },
    {
      "prim": "/RebarModel/Haunch_01",
      "label": "헌치-01",
      "path": ["헌치철근"],                       // 헌치는 하위 분할 없음 — 깊이가 짧아도 됩니다
      "no": 1
    }
  ]
}
```

### 필드 설명

| 필드 | 뜻 | 비고 |
|---|---|---|
| `prim` | USDZ 안 해당 철근 prim 의 **절대 경로** | 이것으로 3D 모델의 철근과 짝을 맞춥니다. **파일 안에서 유일해야 합니다.** |
| `label` | 사람이 보는 최종 이름 | 하이픈·한글·공백 전부 자유입니다. 화면에 이 문자열이 그대로 뜹니다. |
| `path` | 트리 경로 (잎 제외) | **깊이가 부위마다 달라도 됩니다.** 전벽은 3단계, 헌치는 1단계. |
| `no` | 잎 번호 | 같은 `path` 안에서 1부터. |
| `structure` | 트리 루트 이름 | `"옹벽"`, `"벽체"` 등. 한 파일에 구조물이 여럿이면 대표명만 넣고, 구조물 구분은 `path` 첫 칸에 넣어주세요 (예: `["옹벽 A", "전벽철근", "전면", "수직철근"]`). |
| `model_upload_at` | 대상 USDZ 의 `upload_at` | **꼭 넣어주세요.** 아래 「왜 필요한가」 참고. |
| `prim_count` | 그 USDZ 의 철근 prim 총 개수 | 같음. |

### `model_upload_at` · `prim_count` 가 왜 필요한가

모델을 다시 내보내면서 **배근만 바뀌고 prim 이름은 그대로**인 경우가 가장 흔합니다.
이때 계층 정보가 예전 것이면 — 이름이 다 맞으니 짝짓기는 **100% 성공하고**,
라벨만 엉뚱한 철근에 붙습니다. 오류도 경고도 나지 않습니다.

이 두 필드가 있으면 저희가 모델과 대조해 어긋남을 감지하고 "계층 정보가 모델과
맞지 않습니다"를 띄울 수 있습니다. **모델을 다시 내보내실 때 이 JSON 도 함께
갱신해 주시면 됩니다.**

`path` 의 어휘는 위 트리 그림을 그대로 쓰시면 됩니다. 도면 용어와 다른 부분이
있으면 **알려주세요 — 저희가 맞추겠습니다.** 이 값이 그대로 화면에 뜨므로
현장에서 쓰는 용어가 정답입니다.

## 요청 2 — USDZ 변환 시 지켜주셔야 할 것

계층 정보를 3D 모델과 짝지으려면 아래 세 가지가 필요합니다.
(축·단위 요구사항은 `USDZ_REQUEST.md` 그대로이고, 이미 잘 맞고 있습니다.)

### 2-1. 철근 1가닥 = prim 1개

현재 as-built 모델(`ar_type: "visual"`)은 이미 이렇게 되어 있습니다 —
`def Mesh "BotV_01"` 이 60개. **설계 모델도 같은 방식이면 됩니다.**

한 prim 에 여러 가닥이 뭉쳐 있으면 그 가닥들을 따로 선택할 수 없습니다.

### 2-2. prim 이름은 영문·숫자·언더스코어만

USD 규격상 prim 이름은 **식별자**라서 문자 제한이 있습니다.

- ✅ `Stem_Front_Vert_01`, `Base_Top_Trans_01`, `Haunch_01`
- ❌ `전벽-전면-수직철근-01` — **하이픈 `-` 은 USD 규격에서 허용되지 않습니다**
- ❌ `2F_Stem_01` — 숫자로 시작할 수 없습니다
- ❌ 공백, `.`, `/`, `(`, `)` 도 불가

**어기면 조용히 망가집니다.** Blender 의 USD 익스포터는 불법 문자를 `_` 로
바꿔버립니다. 예를 들어 한글 이름을 기본 설정으로 내보내면 —

```
전벽_전면_수직철근_01   →   ___________01
저판_상부_횡방향_01     →   __________01
```

— 이렇게 **모든 철근 이름이 뭉개져 서로 충돌합니다.** 오류 없이 진행되기 때문에
파일만 봐서는 알아채기 어렵습니다.

**한글 이름은 위 JSON 의 `label` 에 담으시면 됩니다.** 거기엔 아무 제약이 없습니다.

> 참고: Blender 를 쓰신다면 `bpy.ops.wm.usd_export(...)` 의 `allow_unicode`
> 옵션이 4.2/4.5 에서는 기본값이 `False` 이고 5.0 부터 `True` 입니다.
> 저희가 이전에 드린 예시 커맨드(`USDZ_REQUEST.md`)에는 이 옵션이 없었습니다.

### 2-3. 철근마다 고유한 메시 데이터

같은 규격 철근이 **지오메트리를 공유**하면(FBX 인스턴싱 / Blender 의 메시 데이터
공유) USDZ 안에서 여러 부재가 같은 메시 데이터를 가리키게 됩니다. Blender 는
오브젝트 이름에는 중복 회피를 걸지만 **메시 데이터 이름에는 걸지 않아서**,
저희 쪽에서 철근들이 서로 뒤섞입니다.

**각 철근 오브젝트가 자기만의 메시 데이터를 갖고, 메시 데이터 이름을 오브젝트
이름과 같게** 맞춰 주세요.

## 확인 부탁드리는 것 (회신만으로 되는 것)

1. **Blender 버전과 실제 변환 스크립트의 `usd_export` 호출 원문**
   (버전에 따라 위 2-2 의 동작이 달라집니다.)
2. **현재 설계 모델(FBX)의 부재 이름이 한글인지 영문 코드인지**
3. **철근들이 지오메트리를 공유하는지** (2-3)

## 먼저 주시면 좋은 것

**옹벽 설계 모델 샘플 USDZ 1개**를 먼저 주시면, 저희가 열어서
가닥별 prim 분리·이름·축·단위가 맞는지 **즉시 확인하고 피드백 드리겠습니다.**
계층 JSON 은 그 뒤에 만드셔도 됩니다.

## 응답 형식·경로가 달라도 됩니다

위 스키마는 제안입니다. **확정된 경로와 필드 이름만 알려주시면** 저희가 그에
맞춰 붙이겠습니다. 필요한 정보는 결국 세 가지뿐입니다 —
**어느 철근인지(prim), 어느 가지에 속하는지(path), 뭐라고 부르는지(label).**

## 참고 — 현재 확인된 사항

- 베이스 URL: `http://api.briconlab.com:50001`
- `GET /analysis/usdz?ar_id=` 는 정상 동작 중입니다.
- site 1/2/3 의 `visual` 모델을 받아 확인했습니다: `model.usda`(텍스트 USD),
  `def Xform "RebarModel"` 아래 `def Mesh` 60개
  (`BotV_01`~`20`, `BotH_01`~`10`, `TopV_01`~`20`, `TopH_01`~`10`),
  `upAxis = "Y"`, `metersPerUnit = 1`. **prim 분리와 이름 규칙 모두 좋습니다.**
- 다만 site 1/2/3 이 **바이트 단위로 동일한 파일**이고 헤더에
  `doc = "As-built rebar model detected from LiDAR scan"` 이 붙어 있어,
  현재는 테스트용 플레이스홀더로 이해하고 있습니다.
- site 4 이상은 `GET /analysis/ar-list?site_id=` 가
  `{"detail": "DB 오류 발생."}` 을 돌려줍니다.

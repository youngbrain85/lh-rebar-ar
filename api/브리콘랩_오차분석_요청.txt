■ 먼저, 잘 받았습니다

설계 모델 prim 이름을 저희가 드린 규약대로 넣어 주셨습니다. 확인했습니다.

  GET /analysis/usdz?ar_id=2  (Mock-up(2)_2.ifc 변환분)
  → def Xform "RebarModel" 아래 def Mesh 45개
     Wall_FrontRear_Shear_01~13, Wall_Front_Horiz_01~09, Wall_Front_Vert_01~09,
     Wall_Rear_Horiz_01~09, Wall_Rear_Vert_01~05
     upAxis "Y", metersPerUnit 1

45개 전부가 발주처 분류표 5개 행에 정확히 매칭됩니다. 저희 앱과 대시보드
양쪽에서 100% 해석되는 것을 확인했고, 이 이름 규약 덕분에 별도 계층 정보
없이도 트리 필터가 동작합니다. 감사합니다.


■ 확인 1. 철근 분석 결과 JSON의 형식 (가장 중요)

  POST /analysis/upload-result
  GET  /analysis/result-download?result_id=

이 두 개가 생긴 것을 봤습니다. 그런데 현재 올라와 있는 3건은 내용이 비어
있습니다.

  GET /analysis/result-download?result_id=3
  → HTTP 200, 4 bytes, 본문이 "{}"
     (result_list 상 3건 모두 remark "테스트", source_filename "test.json")

**이 JSON의 확정된 형식을 알려주실 수 있을까요?**

저희가 만들 화면은 "허용 오차를 넘은 철근을 AR 화면에서 하이라이트"하는
것이라, 최소한 아래 세 가지가 철근 한 가닥마다 필요합니다.

  - 어느 철근인지  (아래 확인 2의 조인 키 문제와 직결됩니다)
  - 판정          (정상 / 허용초과 / 미시공 / 도면외)
  - 편차 크기      (mm)

형식을 아직 안 정하셨다면 저희 쪽 제안을 드릴 수 있습니다. 이미 정하셨다면
그대로 맞추겠습니다 — 저희가 맞추는 편이 빠릅니다.

허용 오차 기준값(무엇을 초과로 볼지)도 결과에 함께 담아주시면, 나중에
"이 판정은 어떤 기준으로 나온 것인가"를 재현할 수 있어 좋습니다.


■ 확인 2. 설계 JSON과 USDZ가 서로 짝지어지지 않습니다

  GET /analysis/design-json?design_id=6&site_id=24
  → 46가닥, 각 항목이 이런 모양입니다

    {"id": "보강 철근:D13 : 모양 보강 철근 모양 1:403612: 1",
     "diaMm": 12.7, "role": "NOTDEFINED", "radiusM": 0.00635,
     "centerline": [[-7.95733, 0.12032, -6.75], [-7.95733, 0.07712, -5.1]]}

같은 IFC(Mock-up(2)_2.ifc)에서 나온 USDZ의 prim 이름은
`Wall_Front_Vert_01` 형태인데, 이 JSON의 `id`는 Revit 요소명입니다.
**두 산출물을 짝지을 공통 키가 없습니다.**

저희에게 이게 왜 문제냐면, 분석 결과가 "어느 철근"을 가리키는지 앱이
알아야 그 철근을 하이라이트할 수 있는데, 앱이 화면에 그리는 것은 USDZ이기
때문입니다. Revit 요소명으로는 USDZ 안의 어느 prim인지 찾을 수 없습니다.

**해결 방법 제안: design-json의 각 항목에 그 철근의 USDZ prim 경로를
같이 넣어 주시면 됩니다.**

    {"id": "보강 철근:D13 : ...:403612: 1",
     "prim": "/RebarModel/Wall_Front_Vert_01",     <-- 이 한 줄
     "diaMm": 12.7, ...}

두 파일 모두 같은 IFC에서 생성하시니, 생성 시점에는 대응 관계를 알고
계실 것으로 짐작합니다. 분석 결과 JSON에도 같은 `prim` 값을 쓰시면
저희 쪽에서 바로 조인됩니다.


■ 확인 3. role 이 전부 NOTDEFINED 입니다

위 design-json 46건의 `role` 값이 예외 없이 `"NOTDEFINED"` 입니다.
분류 정보를 채워 주실 수 있을까요?

이미 USDZ prim 이름(`Wall_Front_Vert_01` 등)에 분류가 들어가 있으니,
같은 근거로 이 필드도 채우실 수 있을 것 같습니다. 발주처 분류표 기준의
값(부재 / 면 / 기능)이면 가장 좋습니다.

없어도 저희는 prim 이름으로 분류하므로 급한 항목은 아닙니다.


■ 확인 4. 철근 개수가 서로 다릅니다

같은 Mock-up(2)_2.ifc 에서 나온 두 산출물의 가닥 수가 다릅니다.

  design-json (design_id=6)  : 46 가닥
  USDZ        (ar_id=2)      : 45 prim

지름 분포는 거의 맞습니다(D12.7 18개, D15.9 18개는 양쪽 동일)만 D22가
JSON 10 / USDZ 9 입니다. 어느 쪽이 맞는지, 한쪽에서 누락 또는 병합이
일어나는지 확인 부탁드립니다.


■ 확인 5. defect-marking 이 FBX 입니다

  GET /analysis/defect-marking?scan_id=   "오차 시각화 FBX 파일 다운로드"

**저희 iOS 앱은 USDZ만 읽습니다.** ARKit/RealityKit 기반이라 FBX를 직접
열 수 없습니다.

두 가지 중 어느 쪽인지 알려주시면 좋겠습니다.
  (가) 이 FBX는 다른 소비자(웹 뷰어 등)를 위한 것이고, 앱은 위 확인 1의
       JSON을 받아서 자체적으로 하이라이트하면 된다
  (나) 앱도 이 파일을 쓰는 것이 전제다 → 그렇다면 USDZ 로도 내주실 수
       있는지

저희 쪽 선호는 (가)입니다. 이미 설계 USDZ를 화면에 띄우고 있으므로,
"어느 prim이 몇 mm 벗어났다"는 정보만 있으면 그 자리에서 색을 입힐 수
있습니다. 별도 파일을 하나 더 받는 것보다 가볍습니다.

참고로 현재 이 엔드포인트는 아래처럼 응답합니다.

  GET /analysis/defect-marking?scan_id=1
  → HTTP 500 {"detail":"DB 오류 발생."}


■ 확인 6. ar_metadata_lh 의 rebar_type 은 어떤 용도인가요

DB에 `ar_metadata_lh` 테이블이 생긴 것을 봤습니다. `rebar_type varchar(32)`
컬럼이 있는데 아직 0행입니다.

철근 종류별로 USDZ를 따로 만드실 계획인지 궁금합니다. 저희는 지금
**하나의 USDZ 안에서 prim 이름으로 걸러내는 방식**으로 종류별 필터를
구현했습니다(LH 전용 앱). 종류마다 파일이 나뉘면 저희 구현과 방식이
달라지므로, 의도를 알면 맞춰가겠습니다.


■ 확인 7. 결과가 0행일 때 500 이 납니다 (이전에 말씀드린 것과 같은 패턴)

  GET /analysis/defect-marking?scan_id=1  → 500 {"detail":"DB 오류 발생."}

데이터가 아직 없어서 0행인 경우로 보이는데, 예외가 아니라 200 + 빈 결과로
주시면 저희 화면에서 "아직 분석 결과가 없습니다"를 정상적으로 안내할 수
있습니다. 지금은 서버 장애와 구분이 되지 않습니다.

예전에 ar-list / scan-list 에서도 같은 패턴이 있었고 지금은 고쳐진 것으로
보입니다. 같은 처리를 이 엔드포인트에도 부탁드립니다.


■ 정리 — 답만 주셔도 되는 것

  1. upload-result / result-download 의 JSON 형식 (확인 1)
  2. design-json 에 prim 경로를 넣어주실 수 있는지 (확인 2)
  3. 46 vs 45 중 어느 쪽이 맞는지 (확인 4)
  4. defect-marking FBX 가 앱용인지 다른 소비자용인지 (확인 5)
  5. ar_metadata_lh.rebar_type 의 용도 (확인 6)

이 중 **1번과 2번이 저희 작업을 막고 있습니다.** 나머지는 확인만 되면
저희 쪽에서 처리하겠습니다.


감사합니다.

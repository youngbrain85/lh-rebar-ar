[요청] 철근 계층 정보 제공 건

안녕하세요. LH 철근 AR 관련해서 요청드릴 게 있어 정리했습니다.


■ 배경

발주처(LH) 요청으로 철근을 계층 구조로 나눠서 트리로 선택·시각화하는
기능을 넣고 있습니다. 분류 체계는 발주처가 준 옹벽 철근 분류표를 그대로
따릅니다.

  부재      면          기능                    prim 이름 토큰
  --------  ----------  ----------------------  ----------------------
  벽체      전면        수직철근                Wall_Front_Vert
  벽체      전면        수평철근(배력철근)      Wall_Front_Horiz
  벽체      배면        수직철근(주철근)        Wall_Rear_Vert
  벽체      배면        수평철근(배력철근)      Wall_Rear_Horiz
  벽체      전면-배면   간격재(전단철근)        Wall_FrontRear_Shear   *
  벽체      상단        보강철근                Wall_Top_Reinf         *
  저판      상부        횡방향철근(주철근)      Base_Upper_Trans
  저판      상부        종방향철근(배력철근)    Base_Upper_Long
  저판      하부        횡방향철근              Base_Lower_Trans
  저판      하부        종방향철근(배력철근)    Base_Lower_Long
  저판      상부-하부   간격재(전단철근)        Base_UpperLower_Shear  *
  벽체-저판  -          보강철근(헌치철근)      WallBase_Haunch        *

  * = 분류표의 "분석 가능할 경우 추가" 항목. 없어도 정상입니다.

주의할 점 두 가지
  - 같은 "수직철근"이라도 면에 따라 이름이 다릅니다. 벽체 전면은 수직철근,
    배면은 수직철근(주철근)입니다. 저판 하부 횡방향철근에도 괄호가 없습니다.
    표의 "기능" 칸을 글자 그대로 넣어주세요.
  - 헌치는 독립 부재가 아닙니다. 벽체-저판 경계의 보강철근이라 이 항목만
    면이 없고 계층이 2단계입니다.

개별 철근이 어느 가지에 속하는지는 도면에만 있는 정보라 저희가 형상만 보고
복원할 수 없습니다. 그래서 모델 만드실 때 알고 계신 그 정보를 함께 주십사
부탁드립니다.

USDZ 파일 형식은 그대로 두셔도 됩니다. 계층 정보는 별도 JSON으로 받습니다.


■ 요청 1. 계층 정보 JSON 엔드포인트

  GET /analysis/rebar-meta?ar_id={ar_id}

기존 usdz 엔드포인트와 같은 ar_id를 씁니다.
계층 정보가 없는 모델이면 404 주시면 됩니다 (저희 쪽에서 자동 분류로
넘어가므로 기능이 죽지는 않습니다).

응답 예시:

{
  "version": 1,
  "ar_id": "51120d35abdc44408520e22b4ff78d7e",
  "model_upload_at": "2026-08-05T10:22:31",
  "prim_count": 248,
  "structure": "옹벽",
  "rebars": [
    {
      "prim": "/RebarModel/Wall_Front_Vert_01",
      "label": "벽체-전면-수직철근-01",
      "path": ["벽체", "전면", "수직철근"],
      "no": 1
    },
    {
      "prim": "/RebarModel/Wall_Rear_Vert_01",
      "label": "벽체-배면-수직철근(주철근)-01",
      "path": ["벽체", "배면", "수직철근(주철근)"],
      "no": 1
    },
    {
      "prim": "/RebarModel/WallBase_Haunch_01",
      "label": "벽체-저판-보강철근(헌치철근)-01",
      "path": ["벽체-저판", "보강철근(헌치철근)"],
      "no": 1
    }
  ]
}

필드 설명
  prim   : USDZ 안 해당 철근 prim의 절대 경로. 이것으로 3D 모델의 철근과
           짝을 맞춥니다. 파일 안에서 유일해야 합니다.
  label  : 사람이 보는 최종 이름. 하이픈·한글·공백 전부 자유입니다.
           화면에 이 문자열이 그대로 뜹니다.
  path   : 위 분류표의 (부재·면·기능)을 그대로. 깊이가 달라도 됩니다 —
           벽체·저판은 3단계, 벽체-저판은 면이 없어 2단계.
  no     : 잎 번호. 같은 path 안에서 1부터.
  structure : 트리 루트 이름 ("옹벽" 등)

  model_upload_at / prim_count : 대상 USDZ의 upload_at과 철근 prim 개수.
  --> 이 두 개를 꼭 넣어주세요. 모델을 다시 내보내면서 배근만 바뀌고 prim
      이름은 그대로인 경우가 가장 흔한데, 그때 계층 정보가 예전 것이면
      이름이 다 맞으니 짝짓기는 100% 성공하고 라벨만 엉뚱한 철근에
      붙습니다. 오류도 경고도 안 납니다. 이 두 필드가 있으면 저희가
      어긋남을 감지해서 사용자에게 알릴 수 있습니다.
      모델 다시 내보내실 때 이 JSON도 같이 갱신해주시면 됩니다.

용어가 도면과 다른 부분이 있으면 알려주세요 — 저희가 맞추겠습니다.
이 값이 그대로 화면에 뜨니까 현장에서 쓰는 용어가 정답입니다.


■ 요청 2. USDZ 변환 시 지켜주실 것 3가지

(축·단위는 지금 잘 맞고 있어서 그대로 두시면 됩니다)

2-1. 철근 1가닥 = prim 1개

  지금 as-built 모델(ar_type "visual")은 이미 이렇게 되어 있습니다.
  def Mesh "BotV_01" 이 60개. 설계 모델도 같은 방식이면 됩니다.
  한 prim에 여러 가닥이 뭉쳐 있으면 그 가닥들을 따로 선택할 수 없습니다.

2-2. prim 이름은 영문·숫자·언더스코어만

  OK :  Wall_Front_Vert_01,  Base_Upper_Trans_01,  WallBase_Haunch_01
        (위 표의 토큰 + _번호)
  NG :  벽체-전면-수직철근-01   <-- 하이픈(-)은 USD 규격에서 불가
  NG :  2F_Wall_01             <-- 숫자로 시작 불가
  NG :  공백, 점(.), 슬래시(/), 괄호도 불가

  ※ 어기면 조용히 망가집니다. Blender USD 익스포터가 불법 문자를 _ 로
    바꿔버립니다. 예를 들어 한글 이름을 기본 설정으로 내보내면

      벽체_전면_수직철근_01  ->  ___________01
      저판_상부_횡방향_01    ->  __________01

    이렇게 모든 철근 이름이 뭉개져서 서로 충돌합니다. 오류 없이 진행되기
    때문에 파일만 봐서는 알아채기 어렵습니다.

    한글 이름은 위 JSON의 label에 담으시면 됩니다. 거기엔 제약이 없습니다.

    참고: Blender 쓰시면 bpy.ops.wm.usd_export(...) 의 allow_unicode 옵션이
    4.2/4.5에서는 기본값이 False, 5.0부터 True입니다. 저희가 이전에 드린
    예시 커맨드에는 이 옵션이 없었습니다.

2-3. 철근마다 고유한 메시 데이터

  같은 규격 철근이 지오메트리를 공유하면(FBX 인스턴싱 / Blender의 메시
  데이터 공유) USDZ 안에서 여러 부재가 같은 메시 데이터를 가리키게 됩니다.
  Blender는 오브젝트 이름에는 중복 회피를 걸지만 메시 데이터 이름에는
  걸지 않아서, 저희 쪽에서 철근들이 서로 뒤섞입니다.

  각 철근 오브젝트가 자기만의 메시 데이터를 갖고, 메시 데이터 이름을
  오브젝트 이름과 같게 맞춰주세요.


■ 회신만으로 되는 것 3가지

  1. Blender 버전과 실제 변환 스크립트의 usd_export 호출 원문
     (버전에 따라 위 2-2 동작이 달라집니다)
  2. 현재 설계 모델(FBX)의 부재 이름이 한글인지 영문 코드인지
  3. 철근들이 지오메트리를 공유하는지 (2-3 관련)


■ 먼저 주시면 좋은 것

옹벽 설계 모델 샘플 USDZ 1개만 먼저 주시면, 저희가 열어서 가닥별 prim
분리·이름·축·단위가 맞는지 바로 확인하고 피드백 드리겠습니다.
계층 JSON은 그 뒤에 만드셔도 됩니다.


■ 형식이 달라도 됩니다

위 스키마는 제안입니다. 확정된 경로와 필드 이름만 알려주시면 저희가 그에
맞춰 붙이겠습니다. 필요한 정보는 결국 세 가지뿐입니다.
  - 어느 철근인지 (prim)
  - 어느 가지에 속하는지 (path)
  - 뭐라고 부르는지 (label)


■ 참고 (저희가 확인한 현재 상태)

- site 1/2/3의 visual 모델을 받아 확인했습니다.

  (BotV_01~20, BotH_01~10, TopV_01~20, TopH_01~10),
  upAxis "Y", metersPerUnit 1.
  --> prim 분리와 이름 규칙 모두 좋습니다. 설계 모델도 이대로면 됩니다.
- 다만 site 1/2/3이 바이트 단위로 동일한 파일이고 헤더에
  doc = "As-built rebar model detected from LiDAR scan" 이 붙어 있어,
  현재는 테스트용 플레이스홀더로 이해하고 있습니다.
- site 4 이상은 GET /analysis/ar-list?site_id= 가
  {"detail": "DB 오류 발생."} 을 돌려줍니다.

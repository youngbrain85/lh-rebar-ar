# AR 앱 분할 — 기기 검증 체크리스트

두 앱을 같은 iPhone/iPad(LiDAR 탑재)에 설치한 뒤 확인한다. 각 항목은 화면 캡처로 근거를 남긴다.

**주의**: 이 문서를 쓰는 시점에 확인된 것은 **CI에서 두 앱 모두 컴파일에 성공했다**는 것뿐이다
(HEAD `77e7cde` 기준 <https://github.com/youngbrain85/lh-rebar-ar/actions/runs/31010767383>).
아래 항목은 전부 기기에서 아직 실행해 본 적이 없다 — 이 저장소가 있는 PC에는 시뮬레이터도
실기기도 ARKit을 쓸 수 없으므로(시뮬레이터는 ARKit 미지원, 이 PC는 Windows) 사람이
iPhone/iPad에서 직접 확인해야 한다.

| # | 확인 | 기대 |
|---|---|---|
| 1 | 홈 화면 | 두 앱이 **각각 별도 아이콘**으로 존재 (`철근 AR 연구`, `LH 철근검측`) |
| 2 | 두 앱 동시 실행 | 번들 ID 충돌 없이 각각 실행됨 |
| 3 | LH 앱 툴바 | 공유(shareplay) 버튼이 **없음**, 자(ruler) 버튼이 **있음** |
| 4 | 연구과제 앱 툴바 | 자 버튼이 **있음**(2026-08-05부터 양쪽 앱 모두 유지하기로 결정), 공유 버튼도 **있음** |
| 5 | 양쪽 공통 | 현장 선택 → 모델 선택 → 배치가 동작 |
| 6 | 양쪽 공통 | 미세조정(mm/0.1°), 재고정(scope), 삭제가 동작 |
| 7 | 양쪽 공통 | 화면 캡쳐가 사진에 저장됨 |
| 8 | 양쪽 공통 | 미세조정 패드의 **투명도 슬라이더**가 모델을 실제로 반투명하게 만듦 (기존 기능) |
| 9 | 투명도 | 기본값 70%로 배치 직후부터 반투명 |
| 10 | 양쪽 공통 (2026-08-05부터 연구과제 앱도 포함) | 측정이 정상 동작 (실↔실, 모델↔실) |
| 11 | 연구과제 앱 | 공유가 정상 동작 (오피스 대시보드에서 화면이 보임) |
| 12 | 기존 설치 기기(이미 테스터에게 배포된 `kr.lh.rebar-ar`)에서 build 34 업데이트 | 홈 화면 앱 이름이 **`LH Rebar AR` → `철근 AR 연구`로 바뀌어 보임** — 현재 테스터에게 가장 눈에 띄는 변화이므로 이름이 안 바뀌거나 두 앱으로 보이는 등 이상 없는지 확인 |
| 13 | 양쪽 공통, 화면 캡쳐 후 사진 확인 | 캡쳐 사진 하단 각주 첫 줄이 **앱 이름**을 정확히 표시 — 연구과제 앱은 `철근 AR 연구 · <모델명> · <일시>`, LH 앱은 `LH 철근검측 · <모델명> · <일시>` (다른 앱 이름이 찍히면 회귀) |

실패 항목이 있으면 그대로 기록한다. "대체로 동작함"으로 넘기지 않는다.

## 철근 계층 트리 필터 (2026-08-05 추가)

`docs/superpowers/specs/2026-08-05-rebar-hierarchy-design.md` §9 의 V6~V10.
**14~16이 실패하면 앱 내 필터는 설계 자체가 달라진다** — 그 경우 모델 생성 단계에서
부위별로 USDZ를 나눠 받아야 하고, 그건 별도 설계가 필요하다(스펙 §7.5).

| # | 확인 | 기대 |
|---|---|---|
| 14 | LH 앱, 모델 배치 후 **DEBUG 빌드**에서 엔티티 트리 덤프(`ModelAnchorController.dumpEntityTree`) | RealityKit이 USD prim 이름을 `Entity.name`으로 **보존**한다 (`BotV_01` 형태가 보임). 이름이 비어 있거나 뭉개져 있으면 **실패** |
| 15 | 같은 덤프의 mesh 노드 경로 집합 vs 대시보드가 같은 모델에서 뽑은 `Rebar.id` 집합 | 정규화 후 **앱 경로 집합 ⊇ 대시보드 id 집합**. 개수가 다른 것 자체는 정상(대시보드는 반경·길이 필터와 연결요소 분리를 한다) — 원인만 기록 |
| 16 | LH 앱 툴바의 **목록 아이콘**(list.bullet.indent) → 트리에서 그룹 하나 해제 | 해당 철근만 사라지고, **숨긴 철근에 측정 레티클이 스냅되지 않는다** (`isEnabled=false`가 충돌체까지 끄는지 확인 — 저장소에 선례가 없는 동작이다) |
| 17 | 16 상태에서 모델 삭제 후 재배치 | 필터가 그대로 재적용된다 |
| 18 | 다른 모델을 골라 배치 | 필터가 **비워진다** (경로가 안 맞으므로. "필터가 걸린 것처럼 보이는데 아무것도 안 숨는" 상태가 되면 회귀) |
| 19 | 연구과제 앱 | 목록 아이콘이 **뜨지 않는다** (`AppFeatures.rebarFilter = false`) |
| 20 | 트리 상단 배지 | 사이드카가 없으면 `모델 이름 규칙으로 추정 — 도면 확인 필요`가 뜬다. 배지 없이 계층만 보이면 회귀 |
| 21 | 철근이 많은 모델(수백 가닥) | 트리를 열고 그룹을 토글할 때 화면이 1초 이상 멈추지 않는다. 배치 지연도 함께 기록 |

## 철근 종류축 필터 (2026-08-18, 설계모델 ar_id=2)

단위 테스트가 증명하는 것은 로직이지 RealityKit 동작이 아니다. 아래는 기기에서만 확정된다.

| # | 확인 | 실패하면 |
|---|---|---|
| D1 | `#if DEBUG` 덤프(`ModelAnchorController.dumpEntityTree`)의 경로 집합이 45개 prim 이름(`Wall_Front_Vert_01` 등)을 포함하는가 | RealityKit 이 prim 이름을 `Entity.name` 으로 안 준다 → 전체가 「분류 없음」 한 덩어리. 사이드카나 다른 신원 축이 필요하다 |
| D2 | 트리에서 `전면 > 수직철근` 을 끄면 그 9가닥이 화면에서 사라지는가 | 잎 한정 `visiblePaths` 가 안 먹은 것 |
| D3 | 「전체 해제」 후 체크가 자동으로 되돌아오지 않는가 | `matched==0` 원복 로직이 남아 있다 |
| D4 | 숨긴 철근에 측정 레티클이 스냅되지 않는가 | `isEnabled=false` 가 hitTest 를 안 막는다 → 숨길 때 `CollisionComponent` 제거·복원으로 전환 |
| D5 | 부위순 ↔ 종류순 전환에서 체크가 유지되는가 | 잎 value 가 축과 무관하다는 전제가 깨진 것 |
| D6 | 모델 목록에 「설계모델」이 위에 뜨고 열리는가 | `ARModel` 관용 디코딩이 안 먹은 것 |
| D7 | 앱을 껐다 켜도 트리의 면 순서가 전면 → 배면 → 전면-배면 로 같은가 | `order` 정렬이 안 먹은 것 |

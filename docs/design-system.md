# BRICON LAB 디자인 시스템 v1

**대상**: 브리콘랩에 납품하는 모든 화면 — office-dashboard(현장 QA 대시보드), 라이다 철근 스캔 분석 앱, 이후 추가되는 도구.
**목적**: 서로 다른 저장소·프레임워크로 만들어도 **한 회사의 한 제품군**으로 보이게 하는 것.
**최종 수정**: 2026-08-03

---

## 0. 5분 만에 적용하기

프레임워크 무관 스타일시트를 호스팅해 두었다. 링크 세 줄이면 톤이 맞는다.

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+KR:wght@300;400;500;700&family=IBM+Plex+Mono:wght@400;500;600&display=swap" rel="stylesheet">
<link rel="stylesheet" href="https://office-dashboard-xi.vercel.app/brand/briconlab.css">

<body class="bl-ground">…</body>
```

호스팅 자산 (모두 `https://office-dashboard-xi.vercel.app` 하위):

| 경로 | 내용 |
|---|---|
| `/brand/briconlab.css` | 토큰 + 기본 컴포넌트 클래스 (드롭인) |
| `/brand/briconlab-logo.png` | 공식 워드마크 345×60 (심볼+글자) |
| `/brand/briconlab-symbol.png` | 심볼만 51×60 — 좁은 자리·아이콘용 |
| `/brand/briconlab-icon-512.png` | 네이비 타일 + 흰 심볼 512×512 — 파비콘/앱 아이콘 소스 |

> 자산을 원격 링크로 쓸지, 각 저장소에 복사할지는 자유. **오프라인 현장에서 쓰는 화면이라면 복사**를 권한다.

## 1. 디자인 컨셉

> **정밀한 도구, 조용한 배경.**
> 이 화면들은 시공 품질을 판정하는 계측 도구다. 화려함이 아니라 **읽히는 정확함**이 목적이다.

세 가지 원칙:

1. **데이터가 주인공** — 색은 판정에만 쓰고, 나머지는 무채색·네이비로 절제한다. 장식용 컬러 금지.
2. **숫자는 계측값처럼** — 치수·좌표·ID는 고정폭 + `tabular-nums`. 자리수가 흔들리면 눈으로 비교가 안 된다.
3. **배경은 물러선다** — 옅은 점 격자 위에 흰 카드. 그림자는 호버에서만, 아주 얕게.

## 2. 색

### 브랜드

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bl-navy` | `#002961` | 로고와 동일한 회사 네이비. 헤딩·주요 버튼·선택 상태 |
| `--bl-paper` | `#f4f4f4` | 페이지 바탕 (회사 사이트와 동일) |
| `--bl-surface` | `#ffffff` | 카드·패널 |
| `--bl-ink` | `#333333` | 본문 글자 |
| `--bl-rule` | `rgba(0,41,97,.14)` | 얇은 구분선 — 회색 대신 네이비를 옅게 |
| `--bl-dot` | `rgba(0,41,97,.11)` | 배경 격자 점 |

> 네이비는 로고 PNG에서 직접 추출한 값이다(단색 `#002961`). **임의로 밝기를 바꾸지 말 것.**

### 판정 색 — 앱 간 절대 통일

철근 분석 결과를 나타내는 의미 색. 대시보드 3D 뷰어와 스캔 앱이 **같은 색을 써야** 사용자가 두 화면을 오갈 때 헷갈리지 않는다.

| 판정 | 토큰 | 값 | 뜻 |
|---|---|---|---|
| 정상 | `--bl-pass` | `#2f9e44` | 허용오차 이내 |
| 허용초과 | `--bl-warn` | `#f08c00` | 설계 대비 편차가 허용오차 초과 |
| 미시공 | `--bl-missing` | `#e03131` | 설계에 있으나 시공에서 미발견 (설계 위치에 반투명으로) |
| 도면 외 | `--bl-extra` | `#1971c2` | 시공에 있으나 설계에 없음 |
| 설계모델 | `--bl-ghost` | `#8a94a6` | 반투명 회색 고스트 (opacity 0.25) |
| 스캔 메시 | `--bl-mesh` | `#5c7cfa` | 참조 레이어 (opacity 0.3) |

**규칙**: 색만으로 판정을 전달하지 말 것. 항상 **색 + 텍스트 라벨**을 함께 둔다(색각 이상 대응). 3D 뷰어에는 반드시 범례 패널을 띄운다.

### 컨투어 색 — 편차 크기 5단계

판정(합격/불합격)이 아니라 **편차의 크기**를 나타내는 색이다. KDS 10 20 50에 철근 간격
오차 기준이 없어 합격선을 그을 근거가 없으므로, 상한은 화면에서 사용자가 정한다.

| 단계 | 토큰 | 값 | 뜻 |
|---|---|---|---|
| 1 | `--bl-contour-1` | `#2c7bb6` | 0 ~ 상한×0.2 |
| 2 | `--bl-contour-2` | `#abd9e9` | ~ 상한×0.4 |
| 3 | `--bl-contour-3` | `#ffffbf` | ~ 상한×0.6 |
| 4 | `--bl-contour-4` | `#fdae61` | ~ 상한×0.8 |
| 5 | `--bl-contour-5` | `#d7191c` | **상한×0.8 이상** (상한 초과 포함) |

**규칙**: 판정 색과 같은 화면에 놓을 때는 반드시 컬러바(0 ~ ≥상한)를 함께 띄운다.
색만으로는 두 체계를 구분할 수 없다.

## 3. 타이포그래피

| 역할 | 서체 | 비고 |
|---|---|---|
| 본문·제목 | **Noto Sans KR** (300/400/500/700) | 회사 사이트와 같은 계열 |
| 숫자·ID·좌표 | **IBM Plex Mono** (400/500/600) | `font-variant-numeric: tabular-nums` 필수 |

- 제목: `font-weight 600`, `letter-spacing -0.03em`(큰 제목일수록 더 조인다), `line-height 1.2`
- 본문: 13~14px, `line-height 1.55`
- 마이크로 라벨(`.bl-microlabel`): 10px / 600 / `letter-spacing .14em` / 대문자 — 섹션 위 조용한 이정표
- **금지**: 굴림, 돋움, Arial 기본값 방치. 한글 제목에 letter-spacing 양수(자간 벌리기)

```html
<span class="bl-microlabel">SCAN</span>
<h2 class="bl-title bl-title--xl">철근 검출 결과</h2>
<span class="bl-mono">27.4 mm</span>
```

## 4. 바탕과 면

- **점 격자**: 22px 간격, 1px 원형 점, 네이비 11%. `background-attachment: fixed`로 스크롤해도 고정.
  선 모눈(그리드 라인)은 쓰지 않는다 — 카드가 묻힌다.
- **카드**: 흰 배경 + 1px `--bl-rule` 테두리 + `border-radius 4px`. 기본 그림자 없음.
- **호버**: `translateY(-1px)` + `0 6px 18px rgba(0,41,97,.09)` + 테두리 네이비. 140ms.
- **선택**: 왼쪽에 `inset 3px 0 0` 네이비 인디케이터 + `--bl-navy-0` 배경.
- **헤더**: 흰색 86% + `backdrop-filter: blur(8px)` + 하단 헤어라인.

```html
<article class="bl-card bl-card--interactive bl-rise">…</article>
<article class="bl-card bl-card--selected">…</article>
```

## 5. 모션

한 번의 등장, 짧은 반응. 그 이상은 하지 않는다.

- **목록 등장**: `.bl-rise` (6px 아래에서 페이드업, 320ms). 항목마다 `animation-delay: index*35ms`, **12번째에서 상한**을 둬 긴 목록이 느려 보이지 않게 한다.
- **호버**: 140ms ease.
- `prefers-reduced-motion`에서 모두 정지 (CSS에 이미 포함).

```js
el.style.animationDelay = `${Math.min(i, 12) * 35}ms`;
```

## 6. 로고 사용

- 헤더에는 **워드마크**(`briconlab-logo.png`)를 높이 **26px**로. 가로는 `auto`.
- 워드마크 옆에 제품명을 둘 때는 **1px 세로 헤어라인**으로 구분하고, 제품명은 `--bl-ink-dim` 13px.
  회사가 주(主), 제품이 종(從).
- 파비콘·앱 아이콘은 **심볼만** 사용(`briconlab-symbol.png` 또는 `briconlab-icon-512.png`).
  16px에서 워드마크 전체는 뭉개진다.
- 최소 여백: 로고 높이의 **0.5배** 이상.
- **금지**: 색 변경, 비율 왜곡, 그림자·외곽선 추가, 네이비 아닌 배경 위에 원본 그대로 올리기(어두운 배경에는 흰색 반전 버전을 따로 준비).

```html
<img src="/brand/briconlab-logo.png" alt="BRICON LAB" style="height:26px;width:auto">
```

## 7. 화면 패턴

이미 대시보드에서 검증된 구성. 스캔 앱도 같은 뼈대를 쓰면 학습 비용이 없다.

### 7.1 정보 위계
```
헤더(로고 · 제품명 · 상태)
  └ 좌측 내비 (최소한으로 — 대시보드는 "현장 관리" 하나뿐)
      └ 목록 (카드) → 상세 (탭)
```
**규칙**: 메뉴를 늘리기 전에 "이건 무엇에 속한 기능인가"를 먼저 묻는다. 대시보드는 모든 기능이 *현장*에 속하므로 메뉴가 하나다.

### 7.2 목록 카드
왼쪽에 식별자(mono, 흐리게) → 이름(600) → 보조 정보(배지 + 시각) → 오른쪽에 액션.
빈 상태에는 **다음에 할 일**을 적는다("라이다 앱에서 업로드하면 여기에 나타납니다").

### 7.3 파괴적 동작
삭제는 **인라인 확인**으로. 모달을 띄우지 않고 카드 안에서 한 단계 더 밟게 한다.
문구에 무엇이 함께 사라지는지 명시("철근 데이터·메시·분석결과가 함께 지워지며 되돌릴 수 없습니다").

### 7.4 3D 뷰어
- 좌상단: 레이어 토글(설계모델 / 시공 / 참조 메시) + 판정 필터 칩(판정 색으로 칠한다)
- 우상단: **색상 범례 패널** (반투명 흰 배경, 스와치 + 한글 설명)
- 레이어는 각각 단독으로 볼 수 있어야 한다 — 겹쳐 보기만 강요하지 않는다

### 7.5 오류·상태 표시
- 실패는 **조용히 삼키지 않는다**. 원인을 한국어로 그대로 보여준다(예: "BLOB_READ_WRITE_TOKEN이 설정되지 않았습니다").
- 부분 실패는 부분만 알린다 — 분석은 됐는데 저장만 실패하면 결과는 그대로 두고 노란 배너로 저장 실패만 알린다.

## 8. 접근성 최소선

- 본문 대비 4.5:1 이상 (`#333` on `#f4f4f4` = 10.4:1 ✔, `--bl-ink-dim`은 13px 이상에서만)
- 판정은 색 + 라벨 동시 제공
- 클릭 대상 최소 32×32px
- 포커스 링 제거 금지 (`.bl-input:focus`가 네이비 링을 준다)
- `prefers-reduced-motion` 존중

## 9. 하지 말 것

| 금지 | 이유 |
|---|---|
| 보라·핑크 그라디언트, 네온 | 계측 도구의 신뢰감을 깎는다 |
| 판정 색을 장식에 재사용 | 초록/주황이 의미를 잃는다 |
| 숫자에 비례폭 서체 | 자리수가 흔들려 비교가 안 된다 |
| 그림자 남발 | 종이 위 도면 느낌이 사라진다 |
| 메뉴 추가로 기능 노출 | 기능은 대상(현장/스캔) 밑으로 들어간다 |
| 로고 색·비율 변경 | 납품처 아이덴티티 훼손 |
